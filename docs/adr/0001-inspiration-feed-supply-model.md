# ADR 0001: 灵感无限流供给模型——预生成大池 + 按需补卡 + 每日硬上限

Status: Accepted
Date: 2026-09-20

## Context

WF11 要把灵感推荐从「每轮 build 产 2-5 张、接口吐 3 张」升级为抖音式可无限刷新的 Feed。
供给模型有三个备选：①纯实时（每次翻页 LLM 现生成）；②纯预生成（build 产固定大容量，
刷完即止）；③预生成大池 + 库存低位时后台补卡。每张卡含 AI 改写选题与 AI 推荐理由，
单次 LLM 调用有 5-15s 延迟与可计成本，且接口可被多标签页/脚本高频请求。

## Decision

采用方案③：build 预生成约 30 张 active 卡；Feed 读取为纯 DB 路径；当库存 ≤8 张时
fire-and-forget 触发 top-up（每批 10 张，带在途锁防并发）；每用户每日出卡硬上限 100 张，
到达后返回 no_more 且不产生任何新 LLM 调用。冷启动用户在无个性化池期间消费全局热点流。

## Consequences
- 读取路径零 LLM 延迟（P95 目标 <500ms），LLM 波动/失败对翻页体验不可见，只会回落到库存。
- 成本有硬上界（日人均约 ≤¥1），账号被盗用或脚本刷不会造成失控费用。
- 不是数学意义上的无限：重度用户当天会看到诚实收尾态；次日 build 自然换新池。
- top-up 需要在途锁与当日计数；锁先以短 TTL 标记实现，若实测多实例失效再落库（spec 已留口）。
- 未来接入真实定时热点/多平台源时，只改池子的供给方，feed 接口契约与上限语义不变。
